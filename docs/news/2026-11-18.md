# BarkBot · Wednesday 18 November 2026

6 pull requests merged, a quiet day after Tuesday's 25. BarkBot is rebuilt to match Grok Bot (the oracle), the app it is measured against, from recorded traces of what that app does. Two changed the app, and one fixed the script that builds the chat host on the bot's computer. Two changed only the rules (the checks the app must pass), and one was Tuesday's News.

## What a person can now do

**Pick a voice** ([#205](https://github.com/FRIKKern/barkbot/pull/205)). In the Voice chat card:

1. Click the Voice, Speed or Language row. Its picker opens with the row's value checked.
2. Pick another option. The picker closes and the row shows your pick; the other rows keep theirs.
3. Open the same picker again: your pick is checked.

Before this, a pick closed the picker and the row kept its old value. The pick is held in the page only. It is not saved, and picking a bot starts the card again from its first values.

**New Bot hides the rest of the window from screen readers** ([#234](https://github.com/FRIKKern/barkbot/pull/234)). While New Bot is open, the rail (the list of bots down the left), the main column, its header and the side panel are marked `aria-hidden`, as the oracle's trace shows in the same frame the dialog appears. Tab and clicks were already kept inside the dialog, and still are. On close, the app takes back only the marks it set.

## What got harder to break

- **The chat host builds again** ([#243](https://github.com/FRIKKern/barkbot/pull/243)). The chat host is the program on the bot's computer that runs its turns; `scripts/host.sh` builds it from Barkpark's code. A Barkpark change on the 18th made the host need one more of Barkpark's internal folders, which the script did not copy, so a build from that code failed and the host would not start. The script now takes all of Barkpark's internal code. It builds to a new file and swaps it in only when the build succeeds. A failed build keeps the program already built, with a warning, and the next start tries again. The host that was running had never been restarted onto the broken build.
- **Command-key hints** ([#237](https://github.com/FRIKKern/barkbot/pull/237)). Hold ⌘ and the rail shows ⌘1 and ⌘2. A new rule holds them to the oracle's trace: each sits at its recorded place within 1 pt, matches every look the trace records (colour, font, border, padding and more), and is gone when ⌘ is let go. The app already matched on every key the rule judges; before this, no rule read that trace. The behaviour rules now run Chrome at twice the pixel density, because at 1x Chrome draws the hints' 0.5 px border as 1 px. All 242 rules held at 2x.
- **A rule that failed once** ([#244](https://github.com/FRIKKern/barkbot/pull/244)). One rule about a conversation another tab saved to a bot failed once on code that had passed it. Each of its cases loaded a page that moved the Main Bot's record in. When another write of that record got there first, the page showed the line "Your Main Bot was saved from another tab or device" before the case began. The later cases now start with the Main Bot already listed, so they write nothing to it. This changed the test only.

The new rules in #205, #234 and #237 were each shown to fail on main or on a copy of the code broken on purpose, and to pass on the code as merged.

## Where it is slow or rough

- A voice, speed or language pick is not saved, and picking a bot resets it. No trace shows whether Grok Bot keeps a voice per bot. 12 more voices and languages still need a capture ([#205](https://github.com/FRIKKern/barkbot/pull/205)).
- What New Bot does on close is not checked by any rule: the trace ends with the dialog still open. Pinning it needs a new recording through Cancel ([#234](https://github.com/FRIKKern/barkbot/pull/234)).
- The second writer behind the failed rule was never caught in a run. Two page loads of one person at once can both move the Main Bot in, and one then says it was saved from another tab or device; that is how the app is meant to behave ([#244](https://github.com/FRIKKern/barkbot/pull/244)).
- The behaviour rules run on hosted CI only, not on a developer's machine. The trace of the hints records no pixel density; 2x is taken from the oracle's other traces ([#237](https://github.com/FRIKKern/barkbot/pull/237)).
- Restarting the host onto the new build was left for after the merge ([#243](https://github.com/FRIKKern/barkbot/pull/243)).

## Across the projects

Barkpark's chat API is what BarkBot talks to. On the 18th one Barkpark change made text cuts never split a flag emoji in half, and put that cut in a new shared folder the chat host now uses ([FRIKKern/barkpark#27039](https://github.com/FRIKKern/barkpark/pull/27039)). That is the change that broke the host's build, fixed in [#243](https://github.com/FRIKKern/barkbot/pull/243). Eight more Barkpark pull requests that day were about asks, where a bot asks before it acts. BarkBot sends a person's answer to an ask through Barkpark's approval call. Barkpark now cancels an ask whose answer the bot's computer refused, instead of leaving it "allowed" ([FRIKKern/barkpark#26949](https://github.com/FRIKKern/barkpark/pull/26949)).
