# BarkBot · Sunday 15 November 2026

BarkBot went from one bot to many. Six pull requests merged: four built many bots end to end, one taught the bot to read files in a live run, and one cleaned up the list of what is still missing.

## Many bots

Until this weekend, BarkBot had exactly one bot. Now:

1. Press **Create** in the rail (the list of bots down the left).
2. Type a name and confirm. Cancel, Close, Escape or a blank name write nothing.
3. The new bot appears in the rail and its own empty conversation opens. Reload the page: it is still there.
4. Pick any bot in the rail: you see that bot's conversation, and its **Working** and **Unread** marks stay on its own tile.

How it fits together, in the order it merged:

- **Bots are known by id** ([#58](https://github.com/FRIKKern/barkbot/pull/58)). The rail, the header and the details panel used to find a bot by its name, so two bots with the same name were one. Now the name is only a label. Two new rules fail on the old code: picking the second of two bots called "Twin" marked both as current, and renaming one renamed both.
- **Bots live in Barkpark** ([#59](https://github.com/FRIKKern/barkbot/pull/59)). Each bot is its own per-account record in Barkpark (name, shape, colour, computer, conversation), plus one list that keeps the rail's order. The bot you already had moves in on first load, keeping its name and conversation.
- **Create** ([#60](https://github.com/FRIKKern/barkbot/pull/60)). Making a bot writes its conversation first, then its record, and adds it to the list last, so a half-made bot never shows. On the old code 4 of 67 rules fail.
- **Each bot shows its own** ([#61](https://github.com/FRIKKern/barkbot/pull/61)). A fresh review that did not write the code passed it: 81 of 81 behaviour rules; the screen-by-screen comparisons with Grok Bot (the app BarkBot recreates) 2,223 of 2,223 and 63 of 63.

## Where it is slow or rough

- Making a bot took 0.50 s in one timed run and 1.13 s in another on a busier machine. The limit is 1.15 s, so there is little room left. Filed.
- If you pick another bot while a new bot's first message is still opening, that message is lost. Filed.
- The last step (#61) was not tried in a live turn against a real Barkpark server.

## Files

The bot read a text file and a PDF in a live run ([#56](https://github.com/FRIKKern/barkbot/pull/56)). A file card shows its size the way Grok Bot does: "25B" for 25 bytes, no space.

## What is left

The parity list ([#57](https://github.com/FRIKKern/barkbot/pull/57)) is the list of every part of Grok Bot and whether BarkBot matches it. Four more items are done (F8, N5, Q2, T3). Two are partly done (A3, N1), three are open (C1, N2, Q3), and two wait for a decision from the owner (C1, Q1: Grok Bot has no cancel button, and it never asked for leave).

## This week so far

BarkBot spent the week matching Grok Bot's question cards, file cards, picture grids and attachments, then turned to running more than one bot. On the same day, Barkpark merged chat sessions that can name a bot folder ([FRIKKern/barkpark#26451](https://github.com/FRIKKern/barkpark/pull/26451)). That is what lets each new bot work in its own folder, which BarkBot uses on Monday.
