# BarkBot · Friday 20 November 2026

10 pull requests merged, one of them Thursday's News. BarkBot is rebuilt to match Grok Bot (the oracle), the app it is measured against, from recordings of what that app does. Two changed what a person sees in the app. Two read Grok Bot 1.2.3 again. Two changed how a computer joins as the bot's host, and three made the live checks and the rules (the checks the app must pass) stricter.

## What a person can now do

**Send the first message to a new conversation** ([#287](https://github.com/FRIKKern/barkbot/pull/287)). On Thursday this was the open snag: a new bot's, or a new computer's, first message was never sent. On a conversation with no rows yet, Barkpark sends no body for 30 s, the app's stream waited for that, and the page gave up at 10 s. The app's stream now opens at once. To try it:

1. Start a new conversation: a new bot, or a bot on a new computer.
2. Type a message and send it.
3. It is sent once, to the new conversation, with no error line.

Seen live, the fixed stream on a fresh, empty conversation answered in 0.03 s. A new rule plays a Barkpark stand-in (a fake Barkpark used in tests) that stays quiet the same way; it fails on the old code ([#287](https://github.com/FRIKKern/barkbot/pull/287)). A later change made its control prove the stand-in sent no body ([#290](https://github.com/FRIKKern/barkbot/pull/290)).

**A fresh conversation on the bot's virtual machine** ([#288](https://github.com/FRIKKern/barkbot/pull/288)). With #287 in, the page's first message made a new conversation on the VM. The reply came in 7.4 s, one message and one answer, and the same after a reload. A cancel re-run there ended as interrupted in 984 ms, with no child process of the host program left. The move off the Mac is not done, so this is still marked partial.

**The Voice chat card on Grok Bot 1.2.3** ([#284](https://github.com/FRIKKern/barkbot/pull/284)). In the details panel's Voice chat card:

1. Voice is one row, a button reading "Helix 1.0x". The Speed row and the Add to Slack row are gone, and the rows below move up 36 pt.
2. Click it. The Voice dialog opens: a Speed slider from 0.5x to 2x over a grid of 28 voices, two to a row, with the picked voice in its middle and focus on it.
3. Pick a voice. The row changes at once and the dialog stays open, as the oracle does ([#285](https://github.com/FRIKKern/barkbot/pull/285)).
4. Language lists all 29 languages.

In Gate A (the gate that measures each captured oracle screen against ours), the Voice picker went from 26 to 109 of 121 cases and the Language picker from 26 to 58 of 70. Both list-end screens now pass every case (40 and 16). The same panel fix raised four other screens by 13 cases each, checked but not recorded.

**Host enrollment from a script** ([#289](https://github.com/FRIKKern/barkbot/pull/289), [#291](https://github.com/FRIKKern/barkbot/pull/291)). BarkBot's host script hands the one-time code to Barkpark's host program on its input. With no terminal, the script now takes a piped-in code; before, it stopped. A pasted code with no newline at the end is kept, and an empty input says "no enrollment code given". When the Barkpark checkout is there and the host program was built before it could read the code this way, enroll is refused before the script asks for the code, with a hint to fetch Barkpark and run again; otherwise the same hint comes after the host program's own error. The script rebuilds first. Ctrl-C while typing the hidden code gives the terminal its echo back.

## What got harder to break

- **The live checks stay on their own conversation** ([#288](https://github.com/FRIKKern/barkbot/pull/288), [#294](https://github.com/FRIKKern/barkbot/pull/294)). The live send check refuses, and sends nothing, when the open conversation is on a different computer from the one it was told to use. The live cancel check stops only a turn that started after its own message. A rule in the checks catches the 15 planted ways to send outside the live send check's one send step; each went red.
- **Enrollment** ([#289](https://github.com/FRIKKern/barkbot/pull/289)). A new check now guards how both enrollment scripts hand over the code.

The behaviour rules now number 251 ([#287](https://github.com/FRIKKern/barkbot/pull/287)), and all 251 held on the day's last merge ([#284](https://github.com/FRIKKern/barkbot/pull/284)).

## The oracle, read again

- **The Voice picker** ([#285](https://github.com/FRIKKern/barkbot/pull/285)). Read on Grok Bot 1.2.3, in a throwaway bot named Oracle: 28 voices, each with a name and a short line ("Elegant & refined"). A pick leaves the picker open. It opens scrolled to the chosen voice, with focus on it. The slider has 16 positions, 1.0x and 1.1x one step apart, so 0.5x to 2.0x in 0.1x steps; the ends are worked out, not seen. A new screen shows the list at its first voice.
- **The pointer is parked** ([#292](https://github.com/FRIKKern/barkbot/pull/292)). A capture now parks the pointer near the window's corner unless told to hover, as the sweep of all screens does. Suggested's Hide button shows only while the pointer is over the window, so Gate A could not judge it before. Five screens made by sends were captured again; all five now have Hide. Four pass more cases than before; one passes fewer, on purpose (below).

## Where it is slow or rough

- **A real Grok frame we do not draw yet** ([#292](https://github.com/FRIKKern/barkbot/pull/292)). The new take of the pictures-sent screen went from 54 of 71 to 34 of 75 cases, accepted on purpose. It shows a time row ("Today 11:31 PM") above the file card and an answered question card cut off at the top. BarkBot draws neither, so the file card and picture tiles sit 26 pt off.
- **The Voice card's open ends** ([#284](https://github.com/FRIKKern/barkbot/pull/284)). "Helix 1.0x" is fixed in the code, and a pick is lost on reload. The preview buttons play nothing, because there is no voice source. The slider's blue focus ring and its rolling digits are not built. The new first-voice screen scores 0 of 48, with no scene yet ([#285](https://github.com/FRIKKern/barkbot/pull/285)). In the voice screens, what still fails is in the conversation behind the card: its first card and first answer bubble.
- **Not tried live**: a real enrollment with a live code ([#289](https://github.com/FRIKKern/barkbot/pull/289), [#291](https://github.com/FRIKKern/barkbot/pull/291)), and a case where the cancel check meets a turn that is not its own ([#288](https://github.com/FRIKKern/barkbot/pull/288)). Gates B and C were not run on the five new takes ([#292](https://github.com/FRIKKern/barkbot/pull/292)).
- The move from the Mac to the virtual machine is not done yet, so that step stays partial ([#288](https://github.com/FRIKKern/barkbot/pull/288)).

## Across the projects

Barkpark runs the chat API and the chat host program BarkBot uses. On the 20th three Barkpark changes carried on with how a machine joins a workspace as a chat host. The workspace owner can make a new one-time code for a host still waiting to join, and the old code stops working at once ([FRIKKern/barkpark#27643](https://github.com/FRIKKern/barkpark/pull/27643)). With the workspace owner's token, `bp chat-host add --ssh` registers a machine in one step, with no code to copy ([FRIKKern/barkpark#27651](https://github.com/FRIKKern/barkpark/pull/27651)). Studio's Chat hosts page is rebuilt: it explains what a chat host is, each machine is a card that says its state in words, and for the workspace owner, Make a code hands over the command to run, with a Copy button; admins are told to ask the owner ([FRIKKern/barkpark#27665](https://github.com/FRIKKern/barkpark/pull/27665)). BarkBot's host script hands the code the same way that command does, on the host program's input ([#289](https://github.com/FRIKKern/barkbot/pull/289)).
