# BarkBot · Sunday 22 November 2026

10 pull requests merged, one of them Saturday's News ([#300](https://github.com/FRIKKern/barkbot/pull/300)). BarkBot is rebuilt to match Grok Bot (the oracle), the app it is measured against, from captures of what Grok Bot 1.2.3 shows. Four changed what a person sees, two raised Gate A scores, and three made the checks harder to fool.

## What a person can now do

**Settings shows this computer and this build** ([#299](https://github.com/FRIKKern/barkbot/pull/299)).

1. Open Settings from the account menu and go to Computer. "Last opened … ago" now comes from the host's real last-seen time. With no value it shows a placeholder bar.
2. Leave Settings open while the computer comes back. The line updates from the 5 s poll, with no reload.
3. Go to Updates. The version is the app's own build, the short git commit unless one is set. "You're up to date" is a placeholder, since nothing checks for updates yet.

**Two files with one name** ([#306](https://github.com/FRIKKern/barkbot/pull/306)). Pick two files both named `note.txt` from two folders and send them in one message. The cards read "note.txt (1)" and "note.txt (2)", as Grok Bot's do. A single file has no number, and Barkpark is still sent the real names.

**Menus keep their word** ([#298](https://github.com/FRIKKern/barkbot/pull/298)). Support in the account menu and More in Connect Apps no longer tell a screen reader they open a menu, since they open nothing yet. Open account menu and Composer actions, which do open one, now say so.

**No "Invalid Date"** ([#301](https://github.com/FRIKKern/barkbot/pull/301)). A stored message or conversation whose time cannot be read gets no time row, where it showed "Invalid Date".

## What got harder to break

- Gate A: the Voice dialog with its 28-voice grid scrolled to the top went from 0 to 48 of 48 cases, its biggest gap ([#307](https://github.com/FRIKKern/barkbot/pull/307)). A file waiting to send went from 52 to 66 of 66: a reply under a file card now starts its bubble 10 px into its row, as Grok Bot's does, not 11 ([#308](https://github.com/FRIKKern/barkbot/pull/308)). Settings gave up 4 cases for showing live values (1,977 to 1,973 of 2,103) ([#299](https://github.com/FRIKKern/barkbot/pull/299)).
- Every control that says it opens a menu or dialog must open one. The check now finds every layer from the app's own list of 12, Settings and its pages, Get mobile, the Voice dialog and the Language picker among them, opens each as a person would, and fails when one has no way in. It takes 3.1 s; a wait that never succeeded had made it 17.8 s ([#303](https://github.com/FRIKKern/barkbot/pull/303)). The behaviour rules stood at 280 after it.
- CI now runs the type check on the app, so a scene key the types do not have turns a PR red ([#304](https://github.com/FRIKKern/barkbot/pull/304)). `npm run check` refuses a scene that carries a row overlap or a lift above 0, spacing only the gate drew ([#302](https://github.com/FRIKKern/barkbot/pull/302)).

## Where it is slow or rough

- The build version is read when the dev server starts, so a new commit shows only after a restart ([#299](https://github.com/FRIKKern/barkbot/pull/299)).
- Share still opens nothing ([#298](https://github.com/FRIKKern/barkbot/pull/298)), and nothing checks for updates ([#299](https://github.com/FRIKKern/barkbot/pull/299)).
- A file sent waits at 77 of 78: its time row is 1.8 wider, from a stand-in font. A choice answered fell to 68 of 69, accepted: Grok Bot left a 1 pt gap between two rows in that one capture, and ours does not draw it ([#308](https://github.com/FRIKKern/barkbot/pull/308)).
- The file-numbers rule still has the same broken load wait #303 fixed; its fix comes separately ([#303](https://github.com/FRIKKern/barkbot/pull/303)).
