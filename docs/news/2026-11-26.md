# BarkBot · Thursday 26 November 2026

5 pull requests merged, one of them the News for Wednesday ([#336](https://github.com/FRIKKern/barkbot/pull/336)). BarkBot is rebuilt to match Grok Bot (the oracle), the app it is measured against. Gate A is the check that compares our screens with captures of Grok Bot, case by case. Two PRs changed what the chat does, one how the chat host runs on a Mac, and one how Gate A scores.

## What a person can now do

**The Main Bot takes over only its own conversations** ([#334](https://github.com/FRIKKern/barkbot/pull/334)). The Main Bot's move-in adopts the newest conversation on our computer that no bot holds, and `startChat` keeps a new one as made here. Both now check who made it.

1. Once per server process, BarkBot asks Barkpark which token it is.
2. A conversation is adopted only when Barkpark records that token as its maker. One a workspace-mate's token made, one a person made, or one with no maker (made before Barkpark recorded makers) is passed over.
3. If the read of who we are fails, nothing is adopted and nothing is kept as made here.

A conversation a bot record names still opens, even with no maker. On the old code 5 of 317 behaviour rules fail; with the change all 318 hold.

**An answered question comes back after a reload** ([#335](https://github.com/FRIKKern/barkbot/pull/335)). Answer a single-choice question card, then reload. The card comes back answered, from the row Barkpark keeps, between your message and the reply. Before, a reload dropped it. A stream that reopens and replays its rows never shows the card twice. A pick-several question gets no card, as before.

**On a Mac, the chat host can run as a LaunchAgent** ([#323](https://github.com/FRIKKern/barkbot/pull/323)), a per-user service macOS starts at login. Before, the host ran only while `npm run host` kept a Terminal open.

1. Run `npm run host:install-agent`. The agent starts at login and restarts on failure, as the VM's service does; its logs go to `~/Library/Logs/BarkBot/`.
2. `npm run host:agent-status` shows it, and `npm run host:uninstall-agent` takes it away.
3. Only one host runs at a time: the install refuses while a Terminal host runs, unless `--replace`, and `npm run host` refuses while the agent runs.

No secret is written into the agent's file; the credential stays in the host's own config file.

## What Gate A now measures

A box case scores one painted box on the page. Paint that draws nothing no longer counts ([#337](https://github.com/FRIKKern/barkbot/pull/337)). Each box's opacity is now read with its parents', and a gradient, a shadow, a text colour, a fill or a top border counts only if, at that opacity, it moves a pixel by at least 4 in 255.

- 37 box cases are gone, all of them passing before, and nothing else changed: 2,656 of 2,754 cases pass, against 2,693 of 2,791.
- 33 of them are the page header's gradient from the page colour to clear: a scrim over scrolled content, which the check does not model yet.
- 4 are menus and pickers whose shadow colours are all fully clear.

## Where it is slow or rough

- The LaunchAgent has not run on a real Mac with Node, Go and a Barkpark login. Its 41 checks use a fake `launchctl` and a fake host. Not yet tried: a turn that replies, a restart after a kill, `claude` and `bp` from the agent, and a restart with the turn resumed ([#323](https://github.com/FRIKKern/barkbot/pull/323)). Filed as a task.
- An agent starts only after login. With FileVault on, a Mac that reboots unattended waits at the login window ([#323](https://github.com/FRIKKern/barkbot/pull/323)).
- `startChat` still works on any listed computer: Barkpark records who made a conversation, not whose computer it is ([#334](https://github.com/FRIKKern/barkbot/pull/334)).
- The header scrim is not scored until the check models what scrolls under it ([#337](https://github.com/FRIKKern/barkbot/pull/337)).
