# BarkBot · Thursday 19 November 2026

9 pull requests merged, one of them Wednesday's News. BarkBot is rebuilt to match Grok Bot (the oracle), the app it is measured against, from recordings of what that app does. The oracle updated itself to 1.2.3 and the baseline moved with it, so BarkBot's scores dropped on purpose. Two changes reached the app, and one put the bot's host on a virtual machine of its own. Four changed only the rules (the checks the app must pass).

## What a person can now do

**Two loads that save the Main Bot at once** ([#253](https://github.com/FRIKKern/barkbot/pull/253)). A page load that finds the Main Bot not yet saved under its key saves it there. When two loads do that at once (two tabs, or a load the server kept running), Barkpark takes only the first. The second load now reads the key again. If the record there is a whole Main Bot of this computer, that load shows it with no line and lists it once. The line "Your Main Bot was saved from another tab or device just now…" now shows only when that second read fails or the record there is not a whole Main Bot of this computer. On Tuesday [#191](https://github.com/FRIKKern/barkbot/pull/191) showed the line here by choice, not from an oracle recording, and the next load then added the bot anyway.

**The day and time line in a conversation** ([#260](https://github.com/FRIKKern/barkbot/pull/260)). Above the first row of the transcript sits a line such as "Today 10:01 AM". BarkBot drew it, but not to the oracle's measures. Gate A (the gate that measures each captured oracle screen against ours) now judges it in the two oracle 1.0.3 captures that show it: its type, its text, its box (28 pt tall; x and width within 1 pt) and its gap of 10 to the first row. Ours matched in both, before the baseline moved to 1.2.3 later that day.

**The bot's computer can be a virtual machine** ([#283](https://github.com/FRIKKern/barkbot/pull/283)). The bot's host, the program that runs its turns, now also runs on a VM of its own, beside the Mac. Seen live on 19 November, each turn checked to have run on the VM:

1. Send a message: the reply came in 8.2 s, and the same after a reload.
2. Cancel a running reply: stopped 409 characters in, ended as interrupted in 640 ms, with no child process of the host program left running. This is checked over the API only, because the app has no Stop button yet.
3. Restart the host program, then come back: it was up again within 2 s, and the bot gave back the code from before.

Older conversations still run on the Mac; nothing has moved over yet.

## What got harder to break

- **The details panel's close and open** ([#252](https://github.com/FRIKKern/barkbot/pull/252)). At 1040 wide the oracle's panel goes 320 → 0 on Close and back on open, in 300 ms on one easing curve. A new rule holds ours to that recording: the same timing values, a width that only shrinks (or only grows), and the end reached no sooner than 250 ms and by 500 ms after the click. The app already matched. Four copies broken on purpose (faster, linear, delayed, faster open) each went red.
- **Shift+Enter in Prompt** ([#257](https://github.com/FRIKKern/barkbot/pull/257), [#274](https://github.com/FRIKKern/barkbot/pull/274)). Before this no rule pressed Shift+Enter, so a Prompt box that sent on it would have passed. The rule now reads the oracle's recording: nothing is sent, the characters and the box height match, and the line breaks are exactly the recording's 2. Plain Enter on the same words sends them once and clears the box. The app already matched.
- **The two-loads rule waits for its race** ([#268](https://github.com/FRIKKern/barkbot/pull/268)). The rule from #253 went red on an unrelated merge: on a busy CI machine only one load saved, so the race never happened. The stand-in Barkpark now holds both loads' reads until both have asked, up to 5 s. If the race still does not happen, the rule says so instead of reporting a wrong page. This changed the test only.

The behaviour rules now number 249 ([#274](https://github.com/FRIKKern/barkbot/pull/274)).

## Where it is slow or rough

- **The new baseline** ([#279](https://github.com/FRIKKern/barkbot/pull/279)). 45 screens were captured by looking (41 again, 4 new) and 6 by sends to a bot named Oracle. Gate A now passes 1,032 of 2,004 cases over 51 screens: 11 pass, 40 fail. The most failing cases are in the Voice picker (95), Connect apps (76) and the new Get mobile dialog (59, no scene yet). The Speed control and the Add to Slack hover are gone on 1.2.3, so three screens were dropped. The oracle now has one "Helix 1.0x" voice button, missed 28 times, and its sends ran file, pictures, question, where ours follow 1.0.3's order.
- **A first message to a new conversation is not sent** ([#283](https://github.com/FRIKKern/barkbot/pull/283)). The app's stream holds until Barkpark's first byte, which takes 30 s on an empty conversation, and the page gives up at 10 s. The live send above used a conversation that already had turns. This is filed as a task.
- **The time line's width** ([#260](https://github.com/FRIKKern/barkbot/pull/260)) is tuned for the stand-in font (the plain font used in place of the oracle's); a font change means measuring again.
- **The panel rule judges time one way** ([#252](https://github.com/FRIKKern/barkbot/pull/252)): a curve slower than the recording that still ends by 500 ms passes.
- The behaviour rules run on hosted CI only, not on a developer's machine ([#252](https://github.com/FRIKKern/barkbot/pull/252), [#257](https://github.com/FRIKKern/barkbot/pull/257), [#268](https://github.com/FRIKKern/barkbot/pull/268)).

## Across the projects

Barkpark runs the chat API and the chat host program BarkBot uses. On the 19th three Barkpark changes reworked how a machine joins a workspace as a chat host. A one-time code that once worked now says, when refused, why and what to do next ([FRIKKern/barkpark#27634](https://github.com/FRIKKern/barkpark/pull/27634)). The host program can read that code from its input and prints the reason it got ([FRIKKern/barkpark#27644](https://github.com/FRIKKern/barkpark/pull/27644)); BarkBot's host script builds that program from Barkpark's main, so a machine picks this up on its next build. A workspace owner can list, register and revoke chat hosts with `bp chat-host` ([FRIKKern/barkpark#27646](https://github.com/FRIKKern/barkpark/pull/27646)).
